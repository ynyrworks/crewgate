## Conclusion

<!-- crew:conclusion -->
This version fixes one defect of 0.26.0 that showed only after that release (plan `usage-fixes`, step n48, added on the user's instruction of 2026-11-20). Two steps of the plan stay open on purpose: rerunning the usage statistics after real use (n37) and the user's judgement of them (n42).

**What happened**

- The commit released as 0.26.0 (1225050) was green on all nine CI jobs in run 44549361300, after a rerun: the first attempt of that run failed on Windows Node 22 in a timing test of `hooks-contract` (the hook took 4711 ms on a slow runner, the test allows 3500 ms; the same job took 706 ms in the run before), which also left two macOS jobs cancelled. The release record of 0.26.0 was written before that and does not mention it.
- Pushing `main` and the tag started two more runs on the same commit, and each failed in one macOS job (44558121301 on Node 20, 44558141097 on Node 18), both in the test "a closed pipe never turns a failure into success": a failing command whose pipes were closed by the reader exited 1 instead of 2. This was found after 0.26.0 was published. 0.26.0 stays published as it is.

**Verified**

- CI on rc/0.21 at 8b85fa7 (run 44566678743): all nine jobs green, including the three macOS jobs, once.
- A full local `npm test` on the merged branch with nothing else running: 1219 tests, 1214 passed, 5 skipped, 0 failed.
- The new test drives the real stream-error handler with injected error codes. The worker reported that it fails (3 of 5) when the list is cut back to `EPIPE` alone; the orchestrator did not repeat that control.
- The orchestrator read the handler, the changed test and the CHANGELOG entry and ran the two test files (12 of 12 passed).

**Not verified**

- Whether the macOS defect is really gone. It was intermittent (2 failures in about 11 macOS job runs), so one green run of three macOS jobs is weak evidence. The user decided on 2026-11-20 not to rerun the macOS jobs and to try the plugin on a Mac instead; that trial has not happened yet.
- Which error code macOS returns. It was never observed: the fix covers the likely codes (`EPROTOTYPE`, `ECONNRESET`, `ERR_STREAM_DESTROYED` arriving first) from reading the code, and the test now prints the codes only when it fails.
- The changed closed-pipe test could not be made to fail on the old code on Windows; only the injected-error test has a control.
- Everything listed as not verified for 0.26.0 still stands: no reviewer, refuter or investigator subagent ran with a real model, the question-widget reply of 0.25, and the two skills in real interactive use.

**How the work was reviewed**

- One task, one review round, no findings. The reviewer finished in 13 seconds, so the orchestrator read the change itself as well.
- The `gate.missing (push)` line below is the push of the tag v0.26.0. When 0.26.0 was published the tag push was flagged as having no unused approval: the orchestrator had asked for the four publishing steps in one gate, and one yes counts for one action. All four steps were in the user's approval; later multi-step releases are asked step by step.

**Known and not fixed**

- Two load-sensitive tests: the `hooks-sessionjob` holder test (times out in some full local runs on the development machine) and the `hooks-contract` timing test above. Both are on the to-do list.
