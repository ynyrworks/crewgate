This version carries the second half of the plan `usage-fixes` (steps n24 to n34 and n44). Two steps of the plan stay open on purpose: rerunning the usage statistics after real use (n37) and the user's judgement of them (n42). The user decided on 2026-11-19 to release with the real-run checks half done and to say so.

**Verified**

- CI on rc/0.21 at 53db25f (run 44546042560): all nine jobs green (Ubuntu, Windows and macOS, each on Node 18, 20 and 22). The run before it, on c06d0e4 (run 44521476646), was green on Windows and macOS and failed on all three Ubuntu jobs (14, 2 and 8 failed tests): `crew task accept` refused tasks as "sent back after review round 1 was finalized" although the round was finalized after the return. Cause: the moment a round was finalized was read from the modification time of the round file and compared with event timestamps; on Linux the file time comes from a coarser clock and can be a few milliseconds behind, so a round written just after an event read as older than it. Only flows that do both within milliseconds were hit, which in practice means tests. Fix (8492c29, merged as 53db25f): `crew review finalize` records a `review.finalized` event and the order is taken from the event log; the file time stays only as the fallback for rounds of older versions. The fix was reviewed (no findings); on Windows the worker reproduced the CI message with the product files put back, and the green Ubuntu jobs are the confirmation on Linux.
- Full local `npm test` runs on the merged branch with nothing else running: before the CI fix 1210 tests, 1205 passed, 5 skipped, 0 failed; after it 1214 tests, 1208 passed, 5 skipped, 1 failed. The failure is the `hooks-sessionjob` holder test, which times out in some full local runs on this machine (it also did on 0.24.0 and 0.25.0), passes when run alone and passed in every CI job. It was not fixed and is on the to-do list.
- Every code task has tests that fail with the change turned off, checked by the worker and, for the orchestrator fix below, by the orchestrator.
- Real runs of the CLI in a throwaway project (docs/PLUGIN-FACTS.md, "Real-run checks for 0.26"): the review rule refuses a fix after a send-back and a task with no review, accepts both with `--read-by-orchestrator` and records the rule, the line count and the note; the lesson line appears at session start once a lesson has been seen on three different days.
- `scripts/collect-usage-data.js --stats` on the folder collected from the second machine gives the numbers the orchestrator had counted by hand for the plan (29 refused answers, 66 actions with no recorded approval, merge gate 151 asked / 141 yes / 2 no, 47 drift questions, 248 accepted tasks, 42 lessons added and none promoted, 24 plans created / 23 finalized / 6 closed); "accepted with no review round" differs by one (87 against 88) and was not traced.
